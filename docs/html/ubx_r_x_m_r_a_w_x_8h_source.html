1/*
2 ubxRXMRAWX.h
3
4 v4 scaffolding: UBX-RXM-RAWX - implemented as its own Class, per AGENTS.md
5 "Implement each UBX message in its own Class". Like NAV-SAT/NAV-SIG/RXM-MEASX (see
6 ubxNAVSAT.h/ubxNAVSIG.h/ubxRXMMEASX.h), RAWX's payload is variable length: a fixed 16-byte
7 header (rcvTow, week, leapS, numMeas, recStat, version) followed by 0..UBX_RXM_RAWX_MAX_BLOCKS
8 identically-shaped 32-byte per-measurement blocks - see u-blox_structs.h's
9 UBX_RXM_RAWX_header_t/UBX_RXM_RAWX_block_t and AGENTS.md "Adding the variable-length UBX
10 messages". Same mechanism as NAV-SAT/NAV-SIG - nothing new needed designing for the
11 variable-length shape itself.
12
13 New territory for THIS message specifically: rcvTow/prMes/cpMes are 8-byte IEEE-754 doubles and
14 doMes is a 4-byte IEEE-754 float - the first field table anywhere in this codebase to use the
15 UBX_CFG_R8/UBX_CFG_R4 data types. extractFieldFrom() (ubxMessage.h) already has working R4/R8
16 cases (byte-reassemble little-endian, then memcpy into value->R4/R8), they just haven't been
17 exercised by any registered message until now.
18
19 'ubxFields' below describes the header only, read with the ordinary
20 getUbxMessageField()/getUbxMessageFieldCallback(). 'recStat' also has two named 1-bit
21 sub-bitfields (leapSec, clkReset). 'ubxBlockFields' describes one repeated block, with offsets
22 relative to the START OF THE BLOCK (not the message) - read with
23 getUbxMessageBlockField()/getUbxMessageBlockFieldCallback(), passing the block index
24 (0..numMeas-1) returned by the "numMeas" header field above. 'trkStat' has four named 1-bit
25 sub-bitfields (prValid, cpValid, halfCyc, subHalfCyc).
26
27 messageLength is set to UBX_RXM_RAWX_MAX_LEN - the MAXIMUM possible payload, not a fixed wire
28 size - exactly as for NAV-SAT/NAV-SIG/RXM-MEASX. storePayload() (in ubxMessageVector.h) already
29 copies only the actual received length, clamped to it.
30*/
