1/*
2 ubxESFMEAS.h
3
4 v4 scaffolding: UBX-ESF-MEAS - implemented as its own Class, per AGENTS.md
5 "Implement each UBX message in its own Class". Like NAV-SAT/NAV-SIG/RXM-RAWX/RXM-MEASX/
6 RXM-SFRBX/SEC-SIG (see ubxNAVSAT.h etc.), ESF-MEAS's payload is variable length: a fixed 8-byte
7 header (timeTag, flags, id) followed by 0..DEF_MAX_NUM_ESF_MEAS identically-shaped 4-byte
8 measurement blocks - see u-blox_structs.h's UBX_ESF_MEAS_data_t and AGENTS.md "Adding the
9 variable-length UBX messages".
10
11 Two things are new here, beyond the ordinary variable-length-block mechanism:
12
13 1. The header's own block-count field ("numMeas") is documented by u-blox as "optional, can be
14 obtained from message size" - i.e. not guaranteed to be populated correctly by the receiver.
15 'blockCountField' below ("numMeas") tells the base class to cross-check it defensively against
16 the message's actual received byte length rather than trust it outright - see
17 ubxMessage::getBlockCount() and DevUBLOXGNSS::getUbxMessageBlockCount()/...Callback() in
18 u-blox_GNSS.cpp.
19 2. ESF-MEAS can include an OPTIONAL trailing 4-byte footer group ("calibTtag") after the last real
20 measurement block - similar in spirit to the NMEA GSV "footer". Whether the GNSS module ever
21 actually outputs it is not clear (u-blox's own note: "calibTtagValid... Always set to zero", so
22 that flag bit cannot be used to detect it either) - per AGENTS.md "Adding support for
23 ESF-MEAS": "For safety, we should assume that ESF-MEAS output by the GNSS can include
24 calibTtag." 'ubxFooterFields' below describes it; its presence in any one particular received
25 message is determined defensively from that message's actual byte length (not from a flag bit,
26 and not from the footer bytes themselves, which can be stale leftovers from a previous, longer
27 message sharing the same storage) - see ubxMessage::extractFooterFieldFrom() and
28 DevUBLOXGNSS::getUbxMessageFooterField()/...Callback().
29
30 'ubxFields' below describes the header only, read with the ordinary
31 getUbxMessageField()/getUbxMessageFieldCallback(). 'ubxBlockFields' describes one repeated 4-byte
32 measurement block, with offsets relative to the START OF THE BLOCK (not the message) - read with
33 getUbxMessageBlockField()/getUbxMessageBlockFieldCallback(), passing a block index up to (but not
34 including) the DEFENSIVE block count returned by getUbxMessageBlockCount()/...Callback() - NOT the
35 raw "numMeas" header field value, for the reason given above. 'ubxFooterFields' describes the
36 optional trailing calibTtag group, read with getUbxMessageFooterField()/...Callback().
37
38 dataField is a 24-bit sub-field, the same width as SEC-SIG's centFreq - it needs the FULL 32-bit
39 union member to read back correctly (X4/U4, not U1) - see ubxSECSIG.h's file header comment for
40 the full explanation of why. dataType (6 bits) fits within a single byte of the union, so U1 is
41 correct for it, exactly like SEC-SIG's jamState/spfState sub-fields.
42
43 numCallbackCopies is UBX_ESF_MEAS_CALLBACK_BUFFERS (u-blox_structs.h), the same
44 ring-buffered-callback-storage mechanism built for RXM-SFRBX - several ESF-MEAS messages can
45 arrive in a group within a single checkUblox() call. Per the Phase 26 precedent with RXM-SFRBX
46 (14 buffers assumed in the interface description / v3 library, 50 needed on real ZED-X20P
47 hardware - more than 3x), UBX_ESF_MEAS_CALLBACK_BUFFERS should be treated as a starting point,
48 not a validated figure - it has NOT yet been checked against real hardware traffic. See AGENTS.md
49 "Adding support for RXM-SFRBX" ("Bearing on ESF-MEAS").
50
51 messageLength is set to UBX_ESF_MEAS_MAX_LEN - the MAXIMUM possible payload (8-byte header + 31
52 measurement blocks + 4-byte footer), not a fixed wire size - exactly as for the other
53 variable-length messages. storePayload() (in ubxMessageVector.h) already copies only the actual
54 received length, clamped to it, and records that actual length in _actualLength/
55 _callbackActualLength for the defensive block-count/footer logic above to use.
56*/
