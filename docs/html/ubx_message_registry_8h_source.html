5// v4 scaffolding: message self-registration, modeled on flxDeviceFactory in flux-sdk (see
6// AGENTS.md "Message Class self-registration"). Each per-message header (e.g. ubxNAVPVT.h) ends
7// with ubxRegisterMessage(ubxNAVPVT), which declares a file-scope static builder object. Its
8// constructor runs at static-initialization time (before setup()) purely because the header was
9// included somewhere - no central list to edit. ubxMessageVector's constructor then asks this
10// registry to build one instance of every registered message.
11//
12// A header included from more than one translation unit (true here: both u-blox_GNSS.cpp and
13// the user's own sketch .ino both pull in every ubxNAVxxx.h transitively via
14// SparkFun_u-blox_GNSS_v4.h) gets its own copy of the file-scope static builder per TU, so its
15// constructor runs once per TU. Each run calls registerMessage() with the SAME create() function
16// pointer though - class-template member functions have "vague linkage" and the linker collapses
17// every TU's copy to one address - so registerMessage() de-duplicates by function-pointer value
18// to end up with exactly one registration no matter how many TUs included the header.
