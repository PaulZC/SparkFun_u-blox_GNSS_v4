1/*
2 ubxRXMPMP.h
3
4 v4 scaffolding: UBX-RXM-PMP (0x02 0x72) - PMP raw data, produced by a NEO-D9S. Implemented as its
5 own Class, per AGENTS.md "Implement each UBX message in its own Class", treated as an ordinary
6 variable-length message like NAV-SAT/RXM-RAWX/RXM-MEASX/MON-COMMS/SEC-SIG/ESF-RAW (see
7 u-blox_structs.h's UBX_RXM_PMP_data_t and AGENTS.md "Adding the variable-length UBX messages").
8
9 PMP cannot be polled - it is "Output" only, same convention as ESF-RAW (no getRXMPMP() wrapper;
10 the old v3 API never had one either). The NEO-D9S outputs it by default on all ports; it does NOT
11 support UBX-CFG-MSG, only UBX-CFG-VALSET (setVal8()/setCfgValset(), which is what this library
12 always uses to write msgOutKeys, so this is unaffected).
13
14 IMPORTANT, DELIBERATE LIMITATION - only message Version 0x01 is correctly modelled:
15
16 UBX-RXM-PMP has two real wire layouts, selected by the "version" byte, and unlike SEC-SIG's
17 Version 2 vs Version 3 (Phase 28-29), the two PMP versions do NOT share a byte layout - they
18 genuinely disagree on where fecBits/ebno/userData sit:
19 - Version 0x00: FIXED length (528 bytes always). userData is a fixed 504 bytes, starting
20 immediately after the 20-byte common header (byte 20); fecBits/ebno sit AFTER userData, at
21 bytes 524/526. The old v3 code's own comment: "Note: length is variable with version 0x01" -
22 i.e. NOT variable with version 0x00.
23 - Version 0x01: VARIABLE length (24 + numBytesUserData, up to 528). fecBits/ebno/reserved1 sit
24 immediately after the 20-byte common header (bytes 20/22/23); userData is variable-length
25 (0..504 bytes, per numBytesUserData), starting at byte 24.
26 Byte 2-3 ("numBytesUserData" in the common header) also means something different per version:
27 for Version 0x01 it is the real userData byte count; for Version 0x00 it is unused/reserved.
28
29 The v4 field-table mechanism has one fixed byte offset per field - it cannot represent "this
30 field moves depending on a runtime byte value" - so this class models ONLY Version 0x01's layout,
31 matching the instruction to "treat RXM-PMP like a standard variable-length UBX message": Version
32 0x01 is the one that is actually variable-length. A real Version 0x00 message would be misparsed
33 by this class (its reserved bytes 2-3 would be read as a bogus userData length, and fecBits/ebno/
34 userData would all be read from the wrong offsets) - same category of accepted, deliberate
35 limitation as SEC-SIG Version 1 being left unmodelled (Phase 28). Nothing in this repo has
36 confirmed which version a real NEO-D9S actually outputs - per the Phase 29 SEC-SIG surprise (a
37 receiver's real output can differ from what looks like the "current" documented version), this is
38 worth checking against real hardware before trusting this class outright, exactly as flagged in
39 claude/v4-migration-status.md.
40
41 userData itself is modelled as 0..UBX_RXM_PMP_MAX_USER_DATA (504) repeated 1-byte "blocks" (see
42 ubxBlockFields below) rather than named fields, since it is opaque payload data (PMP correction
43 data for the D9S's downstream receiver), not a struct of named values - the same treatment would
44 apply to any message whose repeated element is a raw byte rather than a multi-field record.
45 "numBytesUserData" is passed as blockCountField, so getUbxMessageBlockCount()/...Callback() give
46 a defensively-clamped count (min of the header field's own value and what actually fits in the
47 received length) - the ordinary ESF-MEAS-style defensive pattern, not the ESF-RAW no-field-at-all
48 fallback, since Version 0x01 DOES have a real count field.
49
50 setRXMPMPmessageCallbackPtr() (the old v3 "push the whole message, including sync/checksum bytes,
51 to another device" API) is NOT reimplemented, per the user's explicit instruction: the generic
52 raw-frame relay mechanism added in Phase 30 (getUbxMessageRawLengthCallback()/
53 getUbxMessageRawPtrCallback(), automatic for ANY message with a callback registered) already
54 covers exactly that use case, for every message, not just PMP.
55*/
