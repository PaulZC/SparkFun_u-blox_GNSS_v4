1/*
2 ubxRXMSFRBX.h
3
4 v4 scaffolding: UBX-RXM-SFRBX - implemented as its own Class, per AGENTS.md
5 "Implement each UBX message in its own Class". Like NAV-SAT/NAV-SIG/RXM-RAWX/RXM-MEASX (see
6 ubxNAVSAT.h/ubxNAVSIG.h/ubxRXMRAWX.h/ubxRXMMEASX.h), SFRBX's payload is variable length: a fixed
7 8-byte header (gnssId, svId, freqId, numWords, chn, version) followed by 0..UBX_RXM_SFRBX_MAX_WORDS
8 identically-shaped 4-byte data words - see u-blox_structs.h's UBX_RXM_SFRBX_data_t and AGENTS.md
9 "Adding the variable-length UBX messages". Same mechanism as NAV-SAT/NAV-SIG/RXM-RAWX/RXM-MEASX -
10 nothing new needed designing for the variable-length shape itself.
11
12 New territory for THIS message specifically: several SFRBX messages can arrive back-to-back in a
13 single checkUblox() call, with no bus delay between them - see AGENTS.md "Adding support for
14 RXM-SFRBX". numCallbackCopies is 14 (not 1, like every other message migrated so far) so that
15 _callbackStorage (ubxMessage.h) is a genuine ring buffer, able to hold a whole burst until
16 DevUBLOXGNSS::checkCallbacks() drains it - see ubxMessageVector::storePayload() (the write side)
17 and DevUBLOXGNSS::checkCallbacks() (the read side, FIFO drain) in u-blox_GNSS.cpp.
18
19 'ubxFields' below describes the header only, read with the ordinary
20 getUbxMessageField()/getUbxMessageFieldCallback(). 'ubxBlockFields' describes one repeated 4-byte
21 data word, with its offset relative to the START OF THE BLOCK (not the message) - read with
22 getUbxMessageBlockField()/getUbxMessageBlockFieldCallback(), passing the block index
23 (0..numWords-1) returned by the "numWords" header field above. The word ('dwrd') is deliberately
24 NOT decomposed into named sub-bitfields here - its bits mean different things depending on which
25 GNSS constellation and subframe it is; decoding that belongs to whatever consumes the raw words
26 (e.g. an ephemeris parser), not to this field table.
27
28 messageLength is set to UBX_RXM_SFRBX_MAX_LEN - the MAXIMUM possible payload, not a fixed wire
29 size - exactly as for NAV-SAT/NAV-SIG/RXM-RAWX/RXM-MEASX. storePayload() (in ubxMessageVector.h)
30 already copies only the actual received length, clamped to it.
31*/
