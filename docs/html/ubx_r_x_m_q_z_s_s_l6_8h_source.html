1/*
2 ubxRXMQZSSL6.h
3
4 v4 scaffolding: UBX-RXM-QZSSL6 (0x02 0x73) - QZSS L6 raw data, produced by a NEO-D9C. Implemented
5 as its own Class, per AGENTS.md "Implement each UBX message in its own Class", treated as a
6 fixed-length message with an opaque repeated-byte payload - the same treatment RXM-PMP (Phase 32)
7 gave its userData. See u-blox_structs.h's UBX_RXM_QZSSL6_data_t and the u-blox D9-QZS 1.01
8 Interface Description (UBX-21031777-QZS), which was consulted for this message's exact field
9 layout and bit-field breakdown.
10
11 QZSSL6 cannot be polled - it is "Output" only, same convention as RXM-PMP/ESF-RAW (no
12 getRXMQZSSL6() wrapper; the old v3 API never had one either - it only ever offered a raw-message
13 callback, setRXMQZSSL6messageCallbackPtr, no field-based one at all). The NEO-D9C outputs it by
14 default on all ports; per the old v3 code's own comment, it does not support UBX-CFG-MSG, only
15 UBX-CFG-VALSET (setVal8()/setCfgValset(), which is what this library always uses to write
16 msgOutKeys, so this is unaffected).
17
18 UNLIKE RXM-PMP: QZSSL6's payload is FIXED length, not variable. The Interface Description gives a
19 single, unconditional 264-byte payload (a 14-byte header, then a fixed 250-byte msgBytes array),
20 with no byte-count field anywhere in the header. So, matching ESF-RAW's precedent (Phase 31) for
21 a message with no block-count field at all, blockCountField is left at its default nullptr here
22 too - getUbxMessageBlockCount()/...Callback() fall back to the actual-length-derived count, which
23 for this message always comes out to the full 250 (264 - 14 header bytes, / 1 byte per block),
24 matching maxBlocks exactly, since the length never actually varies.
25
26 IMPORTANT, PER THE USER'S EXPLICIT INSTRUCTION: numCallbackCopies = UBX_RXM_QZSSL6_NUM_CHANNELS
27 (2), NOT the ordinary single-slot "latest wins" value used by every other output-only status-like
28 message registered so far (MON-COMMS/SEC-SIG/RXM-PMP/ESF-STATUS). QZSSL6 messages are output two
29 at a time - one per L6 reception channel (Channel A / Channel B, decoded by the chName sub-field
30 below) - so a single callback slot would let the second message of a pair silently overwrite the
31 first before checkCallbacks() gets a chance to drain it. This gives QZSSL6 the same ring-buffered
32 callback delivery already used for burst messages like RXM-SFRBX/ESF-MEAS, just with a ring of
33 exactly 2 rather than a larger burst-sized number - and, unlike those two messages' buffer
34 counts, this is an exact instruction (there are always exactly 2 channels), not an estimate that
35 might need raising after real traffic.
36
37 msgBytes (the raw QZSS L6 payload itself, whose format is defined by a different specification,
38 IS-QZSS-L6-001, that this repo does not otherwise model) is opaque payload data, exactly like
39 RXM-PMP's userData, so it is modelled the same way: 0..UBX_RXM_QZSSL6_DATALEN (250) repeated
40 1-byte "blocks" (blockLength = 1) rather than a struct of named fields.
41
42 chInfo (a 2-byte X2 header field) packs four sub-fields, per the Interface Description's bit
43 breakdown: chn (bits 9:8, receiver channel 0 or 1), msgName (bit 10, 0=L6D/1=L6E), errStatus
44 (bits 13:12, 0=unknown/1=error-free/2=erroneous), chName (bits 15:14, channel name 0=A/1=B). All
45 four sub-fields share chInfo's own byte offset (10) as their startByte, with startBit set to
46 their bit position within the 2-byte field (8/10/12/14) - ubxMessage::extractBits() already
47 supports a startBit beyond the first byte, reading as many little-endian bytes as
48 startBit+bitWidth spans (the same mechanism SEC-SIG's 24-bit centFreq (Phase 28) relies on, just
49 spanning via a startBit offset here instead of a wide bitWidth). The raw chInfo value itself is
50 also exposed as a plain X2 field, for a caller that wants to decode it a different way. Following
51 the same single-bit-width convention already used for SEC-SIG's sigSecFlags sub-fields, the
52 1-bit msgName sub-field is tagged L (bool); the 2-bit chn/errStatus/chName sub-fields are tagged
53 U1.
54*/
