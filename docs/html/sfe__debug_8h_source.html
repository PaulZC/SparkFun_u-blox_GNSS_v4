1/*
2 sfe_debug.h
3
4 v4 scaffolding: debugPrint()/debugPrintln() extracted from DevUBLOXGNSS into their own small
5 base class, SfeDebugPrint, so other classes can inherit real, working debug-print support too -
6 not just DevUBLOXGNSS. Added to let ubxMessageVector and nmeaMessageVector print diagnostics
7 from deep inside their own methods (e.g. a full callback ring buffer dropping a message) without
8 a callback or pointer back into DevUBLOXGNSS.
9
10 ubxMessageVector and nmeaMessageVector are owned BY VALUE as public members of DevUBLOXGNSS
11 (ubxMessages, nmeaMessages) - the opposite containment direction from inheritance - and
12 DevUBLOXGNSS's own header (u-blox_GNSS.h) includes ubxMessageVector.h/nmeaMessageVector.h, not
13 the other way around. So this class lives in its own leaf header with no dependency on
14 u-blox_GNSS.h, and DevUBLOXGNSS, ubxMessageVector and nmeaMessageVector each inherit it
15 independently.
16
17 Plain (non-static) inheritance means each of the three gets its OWN copy of _debugSerial/
18 _printDebug/_printLimitedDebug - so on its own, a ubxMessages.debugPrint(...) call would compile
19 but never print anything, because myGNSS.enableDebugging() only ever sets DevUBLOXGNSS's own
20 inherited copy of that state, not ubxMessages'/nmeaMessages' separate copies. `static` shared
21 state would fix that but wrongly couple debug on/off across every SFE_UBLOX_GNSS instance in a
22 sketch. Instead, copyDebugStateFrom() lets DevUBLOXGNSS::enableDebugging()/disableDebugging()
23 (see u-blox_GNSS.cpp) explicitly push its own state onto ubxMessages/nmeaMessages right after
24 updating it, so all three stay in sync per-instance without any shared/static state.
25*/
